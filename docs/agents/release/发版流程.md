# 发版流程说明

> 本文档描述本项目当前的 CI 结构与发版操作流程。
> 位于 `docs/agents/` 下供审查；若采纳请移出该目录。

## 1. CI 概览

仓库有两个 GitHub Actions workflow：

| 文件 | 触发条件 | 作用 |
| --- | --- | --- |
| `.github/workflows/rust-build.yml` | push / PR 到 `main` | 先 `cargo test`，再四平台编译验证 + 打 .deb / 组装 .app，不发布 |
| `.github/workflows/rust-build-release.yml` | 发布 Release（published）/ **推送 `v*` tag** / 手动 workflow_dispatch | 测试 + 编译 + 打包 + 生成 `.sha256` + 上传产物到 Release |

两个 workflow 共用：Rust stable 工具链、`Swatinem/rust-cache` 缓存、`cargo test` 质量门。

## 2. 发版流程

### 触发方式（三种）

```yaml
on:
  release:
    types: [published]   # 网页/命令行发布 Release 时
  push:
    tags: [ "v*" ]       # 推送版本 tag 时（推荐）
  workflow_dispatch:     # 手动触发（只构建上传 Artifacts，不碰 Release）
```

### 操作步骤

1. **改版本号**：只需改 `Cargo.toml` 的 `version`（macOS Info.plist 由 `build.rs` 经 `CARGO_PKG_VERSION` 自动生成，无需手改）。

2. **提交并合并到 `main`**（确保发布的 tag 指向包含本次改动的提交）。

3. **发版**，二选一：

   - **方式 A：推 tag 自动发版（推荐）**
     ```bash
     git tag v1.2.0 && git push origin v1.2.0
     ```
     workflow 跑完后自动创建 Release（`generate_release_notes` 生成变更说明）并附加产物。

   - **方式 B：网页发布 Release**
     GitHub → Releases → Draft a new release → 选/建 tag → 填说明 → **Publish release**。草稿不触发，必须点 Publish。
     ```bash
     # 或命令行等价操作
     gh release create v1.2.0 --title "v1.2.0" --notes "更新说明"
     ```

4. **触发后**：`build` job 按矩阵并行测试 + 编译四个目标并分别打包；`upload-to-release` job 收集全部产物（含 `.sha256`），用 `softprops/action-gh-release@v2` 附加到对应 tag 的 Release。

5. 约几分钟后，产物出现在 Release 的 Assets 里，用户即可在 Releases 页面下载。

> `workflow_dispatch` 手动运行时：若当前引用不是 `v*` tag，`upload-to-release` job 会跳过——用于只验证构建不发布。

## 3. 产物清单

| 平台 | target | 产物文件名 |
| --- | --- | --- |
| Linux | `x86_64-unknown-linux-gnu` | `copy-type-linux-x86_64.deb` |
| Windows | `x86_64-pc-windows-msvc` | `copy-type-windows-x86_64.exe` |
| macOS (Intel) | `x86_64-apple-darwin` | `copy-type-macos-x86_64.zip` |
| macOS (Apple Silicon) | `aarch64-apple-darwin` | `copy-type-macos-aarch64.zip` |

每个产物附带同名 `.sha256` 校验文件。

`build` job 关键步骤：

- 安装 Rust 工具链与目标 target，`rust-cache` 缓存依赖；
- `cargo test --target <target>`；
- `cargo build --release --target <target>`；
- （Linux/macOS）`strip` 瘦身；
- （Linux）`cargo deb --no-build` 打 `.deb`（运行时需 GTK3 与 appindicator 库，依赖由 cargo-deb 自动探测）；
- （macOS）组装 `Copy&Type.app`（二进制 + `OUT_DIR` 中的 `Info.plist`），`ditto` 压成 `.zip`；
- `sha256sum` 生成校验文件，上传 artifact（`if-no-files-found: error`）。

---

## 4. 注意事项

- **版本号单一来源**：只需改 `Cargo.toml`；`build.rs` 的 Info.plist 自动跟随。
- **产物文件名不带版本号**，版本区分依赖 Release 的 tag/页面。
- **macOS 产物未签名/未公证**：首次打开会被 Gatekeeper 拦截，需右键“打开”，或：
  ```bash
  xattr -dr com.apple.quarantine "Copy&Type.app"
  ```
  且未签名应用在二进制变化后，辅助功能授权可能被系统重置，需重新勾选。
- **Windows 产物未签名**：浏览器/SmartScreen 可能提示风险，属预期。
- **心智模型**：合并 = 验证，打 tag（或发布 Release）= 发版。
